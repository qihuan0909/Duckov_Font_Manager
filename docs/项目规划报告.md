> 编写日期：2026-11-06

## 0. 摘要

| 项目 | 结论 |
|---|---|
| 可行性 | **可行**。游戏全部文字由 TextMeshPro（TMP）渲染，字体全部来自预制体序列化数据，游戏代码几乎不在运行时改字体，这对全局替换非常有利。 |
| 接入方式 | 官方 Mod 系统（`Duckov.Modding.ModBehaviour`），**不依赖 BepInEx**。 |
| 核心手段 | Harmony 2.4.1 后置补丁拦截 TMP 组件启用 / 字体赋值 / 字号赋值，再加一层场景加载后的兜底扫描。 |
| 字体来源 | 运行时读取 TTF/OTF/TTC 文件 → `new Font(path)` → `TMP_FontAsset.CreateFontAsset(...)` 动态图集；系统已装字体也可选。 |
| 热切换 | 不重启即时切换；切换游戏语言时自动换字体；监视字体文件夹，新增或替换字体文件后自动重载；可选热键循环切换。 |
| 设置 UI | 自建 UGUI 面板（热键打开 + 在游戏"设置"界面注入入口按钮），可选同时接入 ModConfig。 |
| 兼容性 | 只用后置补丁、不跳过原方法、不改文本内容；提供公开 API 与排除规则；Mod 停用时撤销全部补丁并完整恢复原状。 |
| 预估工作量 | MVP（替换 + 字号 + 热切换 + 基础面板）约 **5～7 个工作日**；完整版约 **10～14 个工作日**。 |

## 2. 逆向调研结论（已用 dnSpy MCP 验证）

### 2.1 环境

- 游戏目录：`E:\SteamLibrary\steamapps\common\Escape from Duckov\`（D 盘那份只有日志，不是有效安装）
- 托管程序集：`Duckov_Data\Managed\`，主要逻辑在 **`TeamSoda.Duckov.Core.dll`**（1802 个类型），`Assembly-CSharp.dll` 很小
- TMP：`Unity.TextMeshPro.dll`（3.x 系列，`CreateFontAsset` 已支持 `enableMultiAtlasSupport`）
- 输入：Unity **新输入系统**（`Unity.InputSystem.dll`，`UIInputManager` 全部基于 `InputAction`）
- 已安装：BepInEx 5 + UnityExplorer（可用于运行时调试，**本 Mod 不依赖它**）

### 2.2 官方 Mod 加载机制（`Duckov.Modding.ModManager`）

- 扫描 `Duckov_Data/Mods/<文件夹>/info.ini` 和 Steam 创意工坊目录
- `info.ini` 必填 `name`；可选 `displayName`、`description`、`version`、`tags`、`publishedFileId`；同目录 `preview.png` 作为封面
- 加载 `<name>.dll`，反射查找类型 **`<name>.ModBehaviour`**，该类必须继承 `Duckov.Modding.ModBehaviour`
- 生命周期：`AddComponent` → `Setup()` → 虚方法 `OnAfterSetup()`；停用时 `OnBeforeDeactivate()` 后 `Destroy(gameObject)`
- 全局事件：`ModManager.OnModActivated / OnModWillBeDeactivated / OnModStatusChanged`
- 依赖 DLL 通过 `Assembly.LoadFrom` 从同目录加载 → `0Harmony.dll` 放在 Mod 文件夹内即可

### 2.3 游戏字体现状（扫描资源文件得到）

| TMP 字体资源 | 所在文件 | 推测用途 |
|---|---|---|
| `ResourceHanRoundedCN-Medium SDF` | sharedassets0 | **主界面字体**（中日韩 + 拉丁字母） |
| `SourceHanSansCN-Heavy SDF` | sharedassets1 | 粗体标题 |
| `Jua-Regular SDF` | sharedassets0 | 韩文 / 装饰字体 |
| `fusion-pixel-12px-monospaced SDF`、`UnifontExMono SDF`、`PressStart2P-Regular SDF` | resources | 像素风 / 小游戏 / 终端 |
| `7segment SDF`、`Inconsolata-SemiBold SDF` | resources | 数码管、等宽数字 |
| `LiberationSans SDF`（含 Fallback / Outline / Drop Shadow 预设材质） | resources | TMP 默认字体 |

**结论**：不能简单地"把所有字体都换掉"——数码管、像素字体换掉会破坏美术风格。设计上采用 **"按原字体映射"**：默认只替换主字体和标题字体，其他字体可在面板中单独开启。

### 2.4 文本组件与字体赋值路径

- 对 `TMP_Text.set_font` 的交叉引用：游戏代码 **0 处**（只有 TMP 自身和 Shapes 库）
- 对 `TMP_Text.set_fontSize` 的交叉引用：仅 `Duckov.CreditsUtility.TextEntry::Setup`（制作人员名单）
- `GameplayDataSettings.UIStyleData.defaultFont` 字段存在，但 getter 没有任何调用
- 伤害飘字 `FX.PopTextEntity` 使用**世界空间 `TextMeshPro`**（非 UGUI），并且是对象池复用
- 旧版 `UnityEngine.UI.Text`：游戏代码未主动赋值字体，可能只有少量残留 → 作为 P2 可选支持

**结论**：字体几乎完全由预制体决定，拦截 TMP 组件的 `OnEnable` / `Awake` 就能覆盖绝大多数情况。少数运行时改字体的情况（其他 Mod、TMP 内部）由 `set_font` 补丁兜底。

已确认存在、可打补丁的目标方法：
`TextMeshProUGUI::Awake / OnEnable`，`TextMeshPro::Awake / OnEnable`，`TMP_Text::set_font / set_fontSharedMaterial / set_fontMaterial / set_fontSize / set_fontSizeMin / set_fontSizeMax / set_enableAutoSizing`

### 2.5 本地化（`SodaCraft.Localizations`）

- `LocalizationManager.OnSetLanguage(SystemLanguage)` 静态事件 —— 语言切换时触发
- `TextLocalizor` 只改 `.text`，**不改字体**；语言 CSV 在 `StreamingAssets/Localization/*.csv`（共 10 种语言）
- 当前语言：`LocalizationManager.CurrentLanguage`

**结论**：游戏本身没有"按语言换字体"，所以中日韩字形都靠主字体或回退链覆盖。本 Mod 可以订阅 `OnSetLanguage` 实现"按语言自动换字体"。

### 2.6 设置界面 / 输入 / 场景

- 设置面板：`Duckov.Options.UI.OptionsPanel`（私有 `List<OptionsPanel_TabButton> tabButtons`，私有 `Setup()`），标签按钮 `OptionsPanel_TabButton`（私有 `tab`、`selectedIndicator`）
- 设置项组件模板：`OptionsUIEntry_Dropdown / _Slider / _Toggle`
- 游戏设置存档：`OptionsManager`（ES3 → `Options.ES3`）。**本 Mod 不写入游戏存档**，避免污染
- 屏蔽游戏输入：`InputManager.DisableInput(GameObject source)` / `ActiveInput(source)`（基于来源集合，可以和其他界面叠加）
- 暂停菜单：`PauseMenu.onPauseMenuOn / onPauseMenuOff`
- UI 取消键：`UIInputManager.OnCancel / OnCancelEarly`
- 场景事件：`SceneLoader.onStartedLoadingScene / onFinishedLoadingScene / onAfterSceneInitialize`

### 2.7 Mod 生态

- 创意工坊中 5 个以上 Mod 自带 `0Harmony.dll` **2.4.1.0**（另有 DuckMarket 用 2.3.3）→ 选用 **2.4.1** 与主流保持一致
- **ModConfig**（工坊 3590674339）：克隆游戏 OptionsPanel 的标签页生成"Mod Settings"，对外提供静态 API `AddDropdownList / AddInputWithSlider / AddBoolDropdownList / AddOnOptionsChangedDelegate` → 可做**软依赖**接入（反射调用，没装也不影响）
- 官方示例 Mod：DisplayItemValue（工坊 3532400883，作者 xvrsl）可作为工程模板参考

## 3. 总体架构

```
                         ┌─────────────────────────────────────────────┐
                         │      DuckovFontManager.ModBehaviour         │  入口（官方 Mod 系统）
                         │  OnAfterSetup → 初始化 / OnBeforeDeactivate → 全量恢复 │
                         └───────────────┬─────────────────────────────┘
        ┌──────────────┬────────────────┼──────────────────┬──────────────────┐
        ▼              ▼                ▼                  ▼                  ▼
  ConfigService   FontLibrary     TextRegistry        PatchService       UI (SettingsPanel)
  JSON 读写/迁移   字体发现/加载    弱引用登记所有         Harmony 补丁        自建 UGUI 面板
  变更事件         TMP 资源缓存     TMP_Text + 原始状态    + 兜底扫描器        + 设置界面入口按钮
        │              │                ▲                  │                  │
        │              ▼                │                  ▼                  │
        │      MaterialMapper           │           FontApplier  ◄────────────┘
        │      原材质风格→新材质          └──────────── 映射规则/字号/排除规则计算
        ▼
  HotSwitchService：设置变更 / 语言切换 / 文件监视 / 热键 → 批量重新应用（分帧）
        │
        ▼
  Integrations：ModConfig 软依赖、公开 API（FontManagerAPI）
```

**数据流**：任何 TMP 组件启用 → 补丁通知 `TextRegistry` 登记（首次登记时保存原始字体、材质、字号）→ `FontApplier` 按规则计算目标状态并应用 → 设置变化时 `HotSwitchService` 遍历登记表重新计算。

## 4. 核心技术方案

### 4.1 字体发现与加载（`FontLibrary`）

**字体来源**（按优先级）
1. 用户字体目录：`<游戏根>/ModConfigs/DuckovFontManager/Fonts/`（Mod 更新不会覆盖，沿用已有 `ModConfigs` 惯例）
2. Mod 自带目录：`<Mod 目录>/Fonts/`
3. 系统字体（可选开关）：`Font.GetPathsToOSFonts()`
4. （P2）AssetBundle 预烘焙字体：`*.fontbundle`，内含现成的 `TMP_FontAsset`（静态图集，画质最好、加载最快）

**加载流程**
```
文件 → FontEngine.LoadFontFace(path) 读取 familyName/styleName（用于列表显示，不建图集）
用户选中后 →
  Font f = new Font(path)                                    // Unity 从文件路径加载字体
  TMP_FontAsset fa = TMP_FontAsset.CreateFontAsset(
        f, samplingPointSize: 64~90, atlasPadding: 6~9,
        GlyphRenderMode.SDFAA, 2048, 2048,
        AtlasPopulationMode.Dynamic, enableMultiAtlasSupport: true)
  fa.name = "DFM_" + familyName
  fa.fallbackFontAssetTable = [原字体资源]                      // 缺字回退到游戏原字体
```
- `.ttc` 字体集合：用 `FontEngine.LoadFontFace(path, faceIndex)` 枚举子字体；`new Font(path)` 只取第一个，必要时走 P2 方案
- 缓存：`Dictionary<string 路径+参数, TMP_FontAsset>`，同一字体只建一次；切换后旧资源延迟释放（等所有引用都换走后再 `Destroy`）
- 用户提供的样例字体 `customfont/AaYiRiBuJianWoXinQiaoQiao-2.ttf`（约 10 MB 中文手写体）作为主要测试字体

### 4.2 替换策略：按原字体映射 + 材质风格迁移（关键难点）

**映射规则**（配置中的 `fontMappings`）：
```
原字体名（支持通配符） → { 目标字体, 字号缩放, 垂直偏移, 是否启用 }
"ResourceHanRoundedCN-Medium SDF" → 用户字体             （默认启用）
"SourceHanSansCN-Heavy SDF"       → 用户字体（粗体样式）  （默认启用）
"*pixel*", "7segment*", "Unifont*" → 不替换               （默认关闭）
"*"                               → 默认规则（其他 Mod 自带字体等）
```

**材质风格迁移**：游戏文字大量使用描边、阴影等预设材质（例如 `LiberationSans SDF - Outline`）。只换 `font` 会丢失这些效果，导致文字变成"素字"。处理方式：
1. 以 `(原材质实例ID, 目标字体)` 为键缓存新材质
2. `new Material(原材质)` 复制着色器、关键字和全部样式参数（描边宽度/颜色、Underlay、Glow、FaceDilate）
3. 替换图集相关属性：`_MainTex` → 新图集，`_TextureWidth/_TextureHeight`，`_GradientScale` = padding + 1
4. 多图集时 TMP 子网格会自动为每张图集复制材质，不需要额外处理

**缺字回退**：新字体的 `fallbackFontAssetTable` 中放入原字体，确保生僻字、符号、韩文等不会显示成方框。

### 4.3 拦截时机（`PatchService`）

| 补丁目标 | 类型 | 作用 |
|---|---|---|
| `TextMeshProUGUI.Awake` / `TextMeshPro.Awake` | Postfix | 首次登记，保存原始状态 |
| `TextMeshProUGUI.OnEnable` / `TextMeshPro.OnEnable` | Postfix | 应用当前规则（覆盖对象池复用的情况） |
| `TMP_Text.set_font` | Postfix | 外部代码改了字体 → 把它记为新的"原字体"，再按规则重定向（带重入保护） |
| `TMP_Text.set_fontSharedMaterial` / `set_fontMaterial` | Postfix | 外部切换预设材质 → 映射为对应的新材质 |
| `TMP_Text.set_fontSize` / `set_fontSizeMin` / `set_fontSizeMax` | Postfix | 外部改字号 → 记为新的基准字号，再乘以缩放系数（避免反复叠乘） |

**补丁原则**：只用 Postfix，**绝不使用返回 false 跳过原方法的 Prefix**；`[HarmonyPriority(Priority.Last)]` 保证在其他 Mod 的补丁之后执行；所有补丁体都包 `try/catch`，异常只记录不抛出。

**兜底扫描**（Harmony 不可用或个别遗漏时）：
- `SceneLoader.onAfterSceneInitialize` 后执行一次 `Resources.FindObjectsOfTypeAll<TMP_Text>()` 全量扫描（只处理场景内对象，跳过资源预制体）
- 可选低频增量扫描（默认关闭，每 2 秒一次，用于排查问题）

**重入保护**：自身修改属性时设置 `[ThreadStatic] bool _applying`，补丁检测到后直接返回。

### 4.4 字号修改

- 每个登记的组件保存 `baseFontSize / baseMin / baseMax / baseAutoSize`
- 最终字号 = 基准 × 全局缩放 × 类别缩放 × 映射规则缩放 × 度量归一化系数
- 类别：`UI`（TextMeshProUGUI）、`World`（世界空间 TextMeshPro，如伤害飘字）、`Title`（来源为粗体标题字体）
- 开启自动字号的组件同时缩放 `fontSizeMin/Max`
- **度量归一化（R7）**：比较原字体与新字体的 `faceInfo`（`capLine`、`ascentLine`、`lineHeight` 与 `pointSize` 的比例），自动算出让视觉大小一致的系数；另外提供每个字体的手动微调（字号 ±%、垂直偏移、行距）。垂直偏移通过克隆字体资源后调整 `faceInfo` 实现，不修改任何组件布局
- 可选"溢出保护"：缩放后若文本溢出，自动启用 `Ellipsis` 或 AutoSize（默认关闭，避免改变原设计）

### 4.5 全自动热切换（`HotSwitchService`）

| 触发源 | 实现 |
|---|---|
| 面板修改设置 | `ConfigService.Changed` 事件 → 重新应用；滑块拖动时节流（每 100 ms 一次） |
| 游戏语言切换 | 订阅 `LocalizationManager.OnSetLanguage` → 查 `languageProfiles[语言]` → 切换字体组合 |
| 字体文件变化 | `FileSystemWatcher` 监视字体目录（后台线程只设置标记，主线程处理）→ 重建字体列表；正在使用的文件被替换时自动重载 |
| 热键 | 新输入系统 `Keyboard.current`：打开面板（默认 F7，阶段 0 核实不与游戏冲突）、循环切换字体预设 |
| 场景切换 | `onFinishedLoadingScene` → 兜底扫描 |

**批量应用**：用协程分帧处理，每帧最多处理 N 个组件（默认 300），避免切换瞬间卡顿；处理完成后调用 `ForceMeshUpdate`。登记表使用弱引用并定期清理已销毁的组件。

### 4.6 与其他 Mod 的兼容性

1. **Harmony**：自带 0Harmony 2.4.1；使用唯一 ID `com.duckov.fontmanager`；停用时只调用 `UnpatchAll(自己的ID)`
2. **不改文本内容**：翻译类、显示数值类 Mod 不受影响
3. **其他 Mod 生成的文字**：默认同样替换（这正是"全局"的意义）；提供排除规则
   - 按原字体名排除
   - 按层级路径正则排除（例如 `^ModConfig/.*`）
   - 按组件上的标记排除（其他 Mod 可以添加 `DFM_Exclude` 组件或调用 API）
4. **公开 API**（`DuckovFontManager.FontManagerAPI`，静态类，方便其他 Mod 反射调用）：
   `GetCurrentFont()`、`event OnFontChanged`、`Exclude(GameObject)`、`Include(GameObject)`、`ApplyTo(TMP_Text)`、`GetFontScale()`
5. **ModConfig 软依赖**：检测到 ModConfig 已加载时，通过反射注册几个基础选项（启用开关、字体下拉、全局字号）；没装时完全不涉及
6. **BepInEx 共存**：BepInEx 自带 HarmonyX（0Harmony 2.x 的更高版本），可能出现两个 Harmony 版本同时加载 → 阶段 0 专门做"装 / 不装 BepInEx"两种环境的验证
7. **安全停用（R6）**：`OnBeforeDeactivate` → 撤销补丁 → 遍历登记表恢复原字体/材质/字号 → 销毁生成的字体资源和材质 → 取消所有事件订阅 → 停止文件监视

### 4.7 设置面板（`UI`）

**方案选择**

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. IMGUI（OnGUI） | 开发最快 | 风格与游戏不符，中文显示依赖系统字体，无法预览 TMP 效果 | 仅用作调试面板 |
| B. 克隆游戏 OptionsPanel 标签页（ModConfig 的做法） | 风格完全一致 | 受游戏 UI 结构变化影响大，复杂控件（字体列表、预览）不好做 | 只用来注入一个入口按钮 |
| **C. 代码构建独立 UGUI 面板** | 可控、可做实时预览，可复用游戏的 TMP 字体和精灵保持风格接近 | 工作量中等 | **推荐，作为主面板** |

### 4.9 性能

- 中文动态图集：首次出现的字形需要实时光栅化，会有轻微卡顿 → 提供"预热"：后台按每帧 50～100 字的节奏 `TryAddCharacters` 常用 3500 字（可关闭）
- 内存：2048² Alpha8 图集每张约 4 MB；常用汉字在 72pt 采样下约需 3～5 张 → 约 20 MB，可接受；提供采样字号与图集尺寸选项
- 补丁热路径（`OnEnable` 极其频繁）：O(1) 字典查找；对象池复用的组件已处于目标状态时直接跳过
- 字号滑块拖动节流；批量应用分帧执行

## 8. 风险与对策

| 风险 | 可能性 | 影响 | 对策 |
|---|---|---|---|
| 运行时 `new Font(path)` 对个别字体（OTF CFF、TTC、可变字体）失败 | 中 | 部分字体不可用 | 加载前用 `FontEngine.LoadFontFace` 预检；失败时在面板中标红提示；P2 阶段提供 AssetBundle 预烘焙方案 |
| 材质迁移后描边/阴影效果不一致 | 中 | 观感下降 | MaterialMapper 复制全部样式参数并按新 padding 重新计算 `_GradientScale`；必要时按字体单独微调 |
| 新字体度量差异导致文字偏移、溢出、截断 | 高 | 布局错乱 | 度量归一化 + 手动偏移；字号上限提示；可选溢出保护 |
| 0Harmony 与 BepInEx 的 HarmonyX 版本冲突 | 低～中 | 补丁失败 | P0 专项验证；补丁失败时自动降级为"扫描模式"（每次场景加载 + 启用后扫描），功能基本可用 |
| 游戏更新导致 TMP 或 Mod API 变化 | 低 | 失效 | 补丁只针对 TMP 公共方法（稳定）；游戏 API 全部用反射加 try/catch；启动时自检并记录日志 |
| 首次显示生僻字卡顿 | 中 | 轻微卡顿 | 预热常用字；多图集；采样字号可调 |
| 其他 Mod 的 UI 依赖特定字体的尺寸 | 低 | 其他 Mod 显示异常 | 排除规则 + API；默认只替换游戏原字体时可选"不替换未知字体" |
| 用户分发字体的版权问题 | — | 发布风险 | 发布包不自带商业字体，只提供目录与说明；样例字体是否可随包分发需先确认授权 |

## 9. 需要你确认的决策点

1. **非主字体的默认行为**：像素字体、数码管字体默认**不替换**（推荐），还是默认全部替换？
2. **其他 Mod 自带的字体**：默认替换（更"全局"），还是默认不替换（更安全）？推荐**默认替换 + 可排除**。
3. **设置面板入口**：热键 + 游戏设置界面注入按钮（推荐）；是否还需要接入 ModConfig？
4. **默认热键**：F7 可以吗？
5. **配置存放位置**：`游戏根/ModConfigs/DuckovFontManager/`（推荐，与 DuckovCustomModel 一致）还是 Mod 文件夹内？
6. **是否随包附带字体**：`AaYiRiBuJianWoXinQiaoQiao-2.ttf` 是否有再分发授权？没有的话发布包只放说明。
7. **是否需要 AssetBundle 预烘焙字体**（画质最好，但需要用户安装 Unity 2022.3 制作）：建议放到完整版之后再做。
8. **范围**：先做 MVP（P0～P3）给你试玩再继续，还是一次做到完整版？
